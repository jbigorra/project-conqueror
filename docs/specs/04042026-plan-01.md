<goal>
Create an LLM Agent ready plan to implement a dev friendly facade for Behave and in parallel work on implementing the complexityHotspots enclosure diagram.
</goal>

<reasoning>
By knowing the specs for the enclosure diagram a data inteface can be defined so that the behave facade can be worked on in parallel.
</reasoning>

<Context>
An electrobun aplication will be created in the near future. A user using the application will have to select a folder from their local system where a code repository exists. Based on the absolute location of said repository the Folder's Tree sctructure will be used to build the analyses tree to draw enclosure diagrams and other tree-like diagrams.
</Context>

<Key Results>
1. A very dev friendly facade for Behave is created.
   1. A class named Behave is created, provides a public API to make use of all the analyses it can provide.
   2. Constructing the class allows to pass the gitLogPath absolute path.
   3. Each analysis method in behave receives the analysis option object, avoid setting it in the behave constructuor to avoid having to create a new class if the options needed to be changed.
2. A complexityHotspots enclousure diagram is created with D3js and d3-hierarchy pack.
   1. Needs to exists in the charts package.
   2. Needs to be visible in storybook.
   3. Needs to be implemented by modifying the <pq-hotspots-chart> component.
   4. The diagram needs to be zoomable.
   5. Clicking on a pack needs to zoom into it, reveling any other packs inside.
   6. Hovering over a pack needs to display a tooltip with:
      1. If pack is a folder:
         1. Number of immediate files inside the folder
         2. Number of immediate folders inside
         3. Total number of lines of code (recusively summed)
         4. Total number of folders
         5. Total number of files
      2. If pack is a file:
         1. Lines of code
         2. Complexity score
      3. Pack colors go from light pastel green (low complexity score) to pastel red (high complexity score), in that order based on:
         1.  If a folder:
             1.  The average complexity score contained inside the folder considering children folders and files.
         2.  If a file:
             1.  The complexity score of the file
    7.  The algorithm generating the tree and the aggregated data needs to be performant, not have memory leaks and well-crafted, easy to understand.
</Key Results>
